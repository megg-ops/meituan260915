# 周末拾光 · 周末城市探索指南

美团 AI Coding 笔试作品。线上地址：**https://megg-ops.github.io/meituan260915/**

帮大学生找到这周末去哪，并把每一次城市探索变成一张可以收藏的地点票根。

## 核心链路

```
感到周末临近 → 3 个明确推荐 → 地点详情 → 加入周末计划 → 主动确认到访 → 地点票根 → 我的收集
```

## 产品结构

```
周末拾光
├─ 周末  倒计时 + 当前天气（演示）+ 城市探索示意图 + 地点卡 + 3 个推荐
│        地点详情：推荐理由、攻略、结伴入口、加入计划 / 确认打卡
├─ 组队  同城队伍、加入 / 退出、从地点发起组队
├─ 收集  地点票根、重复到访记录、未解锁地点
└─ 我的  模拟登录／注册、出游伙伴、周末偏好、城市、产品与数据说明
```

- 推荐逻辑：匹配度 = 兴趣 35% + 天气 25% + 预算 20% + 同行 20%，每个推荐写明理由。
- 打卡由用户主动确认，点击地图地点不算到访；伙伴只在打卡后移动到该地点。
- 票根保存打卡时的日期、天气与伙伴；同一地点再次到访记为同一张票根的新记录。
- 票根详情底部提供「查看地点 / 分享票根」。分享使用现有插画，由浏览器原生 Canvas 按最近一次到访生成 900×1410 PNG，预览后保存；不包含邮箱、消费金额与私人留言，不上传、不创建公开票根链接。失败可重试，手机无法直接下载时可尝试长按预览图保存。
- 天气四态（晴 / 多云 / 雨 / 雪）+ 未知；小雨最多 14 条短雨滴、小雪最多 12 颗柔和雪点，错峰飘落。天气面板可关闭动态，尊重系统减少动态设置，后台暂停动画。
- 杭州、北京、上海、广州、深圳均有 B 稿手绘动画风探索示意图与可点击地点；地图不用于真实导航。
- 橘猫采用正面、身体轻微侧转的自然坐姿。新票根保存对应城市取景与伙伴图片版本，已有票根保留旧素材。
- 除西湖独立插画外，其余地点票根暂取景自城市地图，并非每个地点都已单独绘制。
- 活动、天气、队伍与攻略为演示数据；个人数据只保存在本机 localStorage。
- 默认游客进入，「我的」提供模拟登录／注册。任意格式正确的演示邮箱和至少 6 位测试密码可体验，不验证真实账号；仅保存邮箱、昵称和演示登录状态，不保存或发送密码。每位访客的记录保存在其自己的浏览器中，不上传 GitHub 或开发者设备；仅同一浏览器、同一站点来源下的演示身份共用该浏览器的票根和计划，退出不删除记录。不是身份认证系统，不提供账号隔离、找回密码或云端同步。
- 每个页签右上角的音符直接控制音乐：点击播放，再次点击暂停，不弹出播放卡片。首次打开页面不自动播放，主动播放后全应用持续循环，切换页签不会暂停。应用不主动因后台状态暂停，但系统或浏览器仍可能中断音频；刷新或重新打开页面需重新开启。加载中再次点击可取消，失败可点击重试。
- 网页使用 `assets/shiguang-web-v1.mp3`（96 kbps，约 1.8 MB）；用户提供的原始音频 `assets/拾光_no-watermark.mp3` 保留，不参与首屏加载。公开发布前需确认原音频生成平台的使用授权。
- 首页「周末拾光」左侧与浏览器标签使用同一款阳光票根图标；64px WebP 约 1.5 KB，另备 32px PNG。

## 48 小时迭代过程

从 2026-09-15 20:30 首次上线起，48 小时窗口内在同一域名下持续迭代。
协作方式：我负责定方向和评审，AI 负责起草与实现，每一轮经人工验收后再推进。

### 起点：30 分钟原型，先让产品「存在」

拿到题目先用 30 分钟做出单文件原型「周末出发 WeekendGO」：四页签、5 城 17 个活动、可解释的推荐（兴趣 35% + 天气 25% + 预算 20% + 同行 20%）、组队/打卡/攻略，当晚部署上线。它验证了功能闭环可以成立，也暴露了三个问题：视觉是模板化的渐变加 Emoji、首屏没有明确的行动重点、打卡只是一条干巴巴的记录。这三个问题，成了后面所有迭代的起点。

### 产品定义：从「找活动的工具」到「可收藏的纪念」

原型把题目做成了一个决策工具；复盘时我们重新定义了它：

> 帮大学生发现适合自己的周末去处，并把每一次城市探索变成可以收藏的纪念。

这个定义给产品三种价值：决策价值（不用跨平台搜索比价，直接拿到少量明确的推荐）、情绪价值（周末临近的期待和出发的仪式感）、留存价值（每次探索沉淀成一张票根）。「票根」由此成为贯穿全产品的母题，核心体验链路也定了下来：

```text
打开应用 → 感受周末临近 → 表达想怎么玩 → 获得三个推荐 → 出发探索
→ 主动确认打卡、获得票根 → 收入「我的收集」→ 回看分享，产生下一次出发
```

配套的设计原则：先让人想出发，再让人设置条件；每个页面只有一个主行动；推荐少而明确；经历比数据更值得收藏；演示数据必须诚实标注，不伪装成真实服务。

### 用户：大学生和他们周末的三个时刻

目标用户是 18—25 岁、生活在高校或高校周边城市的大学生。他们的周末围绕三个时刻展开：

- **工作日晚**：开始惦记这周末去哪——需要的是期待感，和一个明确的安排入口；
- **周末早晨**：临时决定出发——需要快速拿到少量靠谱的去处，而不是刷一小时攻略；
- **活动结束后**：想留下点什么，也想知道下次还能去哪。

他们的典型痛点：不知道去哪、信息太散、预算有限、找不到同行者、玩过之后没有沉淀。产品围绕这些痛点做取舍：去处偏向学校周边、低预算、公交可达、半日一日可往返；杭州只是视觉样例，产品面向多城市；不做全社会通用的探索平台。

### 功能迭代：每个功能都从一个具体场景长出来

功能不从「还能加什么」出发，而从「用户在哪个时刻需要什么」出发：每个想法先进候选区，评估用户价值与成本档位，再按剩余时间排入优先级。

| 用户时刻 | 功能回应 |
|---|---|
| 周中就开始惦记周末 | 周末倒计时与情境首页，文案随日期变化 |
| 信息太散，比来比去太累 | 每轮只给 3 个推荐，每个写明「为什么适合你」 |
| 玩过之后没有沉淀 | 主动确认到访后生成地点票根，收入「我的收集」 |
| 独自出发，想有个伴 | 可命名、可关闭的橘猫伙伴，打卡后移动到你到访的地点 |
| 天气影响出门与选择 | 晴/多云/雨/雪四态氛围与轻量动效，标注为演示数据 |
| 想把经历讲给朋友听 | 票根一键生成分享图，自动排除邮箱、消费等隐私字段 |

有些「不做」同样由场景推出来：点击地图地点不算到访，打卡必须用户主动确认——否则这份纪念就不真实；高校认证、排行榜、真实天气接入经评估后明确缓做，避免稀释核心链路。进度上设了冻结线：时间失控就砍新增、保完成度。

### 视觉基调与落地节奏

动手改版前先定视觉：从「水彩、动画感、手绘」三个关键词出发，收集四张喜欢的插画参考逐张提炼「学什么、避开什么」，再用 AI 生图做 A/B 两稿评审——A 稿偏写实，B 稿更简化、更有动画场景感，选定 B 稿后把感觉固化成视觉规范（色板、统一光向、2.5D 手绘地图、票面语言）。这一晚只改文档和图，没有动一行代码。

之后分三批落地，每批都在主链路上加厚：

1. **B 稿改版（首夜）**：手绘风全面替换模板视觉，跑通「推荐 → 详情 → 主动打卡 → 票根 → 收集」；
2. **扩展打磨（次日上午）**：杭州样例扩展为五城手绘地图，接入四态天气氛围；
3. **体验与品牌（次日下午）**：票根分享、模拟登录、背景音乐，品牌更名为「周末拾光」。

每一步都保持纯静态、零依赖、无构建，域名始终不变。
